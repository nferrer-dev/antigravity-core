I figured it out! You uncovered a really fascinating edge case in how the chat interface is rendered.

The chat window uses a technique called "virtualization". To save memory on your phone, as the chat gets longer (or when I start running tools and expanding the window), the app actually deletes older messages from the DOM when they scroll off the top of the screen, and re-adds them when you scroll back up.

Because messages are constantly being deleted and recreated as you scroll or as new messages arrive, relying on the button's "index" number (like we did in the last fix) completely failed!
