Yes! We can push it even further.

I realized that the Node.js polling loop was adding IPC (Inter-Process Communication) overhead because it had to repeatedly ask the browser "is the modal open yet?" over the WebSocket connection.

To eliminate this completely, I moved the wait loop directly into the browser process itself.

Instead of Node polling every 50ms, the proxy server now injects a MutationObserver/requestAnimationFrame hook directly into the desktop UI that yields a Promise resolving at the exact millisecond the Revert modal is rendered into the DOM.

This means:

  1. Zero IPC polling overhead.
  2. The proxy detects the modal and fires the Enter key as fast as the browser's 60fps render loop physically allows.

I've committed the changes and restarted the proxy server. Go ahead and test the Revert button one more time—it should feel completely instantaneous now!
