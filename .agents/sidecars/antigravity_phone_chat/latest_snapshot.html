Should we make the accesses of these style guides skills so as to keep the context window lean?
6:36 PM

That is a brilliant application of the Minimal Viable Context (MVC) Protocol!

If we hardcoded all those URLs into AGENTS.md, or forced the subagents to dynamically scrape massive HTML pages via read_url_content on every loop, it would severely bloat the context window, increase API latency, and risk triggering the "Lost in the Middle" hallucination syndrome.

By converting them into individual, language-specific skills (e.g., .agents/skills/style-python, .agents/skills/style-go), we get two massive benefits:

  1. The "Pull" Model: The main AGENTS.md stays lean. The Language-Specific Style Expert will dynamically use view_file to "pull" the specific skill documentation only when it is reviewing a file of that type.
  2. Distillation & Tooling: Instead of just linking to the massive PEP 8 web page, the skill's SKILL.md can contain a distilled version of the core rules, or even better, explicit instructions to run automated linters (e.g., "Run flake8 <file> instead of manually guessing style violations").

Since this involves adding new skills and updating AGENTS.md (which alters global state boundaries), this requires an implementation_plan.md to be formally validated.
